# ADR 0001 — Python 3.12, borne haute assumée

- **Statut** : accepté
- **Date** : 2026-08-05

## Contexte

Le service dépend d'`ultralytics`, qui dépend de `torch`. PyPI ne publie des
roues `torch` que pour `cp310` → `cp313`, et aucune variante CUDA pour `cp314`.
Le Python système de la machine de développement est un 3.14.6.

Sous Python 3.14, deux issues, toutes les deux mauvaises : `uv sync` tente une
compilation de `torch` depuis les sources (des heures, puis un échec), ou
l'installation « réussit » et `import ultralytics` échoue à l'exécution.

## Décision

1. `backend/.python-version` contient `3.12`.
2. `backend/pyproject.toml` déclare `requires-python = ">=3.12,<3.13"`.

La **borne haute est volontaire**. Sans elle, le mode de défaillance est
« l'application plante à l'import de torch », après une installation de plusieurs
minutes. Avec elle, c'est « uv refuse de résoudre », immédiatement, avec la
version demandée dans le message. Le second est diagnosticable, le premier non.

`uv` provisionne l'interpréteur lui-même (`uv python install 3.12`) : le Python
système de la machine n'est jamais utilisé, et aucune installation globale n'est
modifiée.

## Conséquences

- Toute commande backend passe par `uv run`, jamais par un `python` du PATH.
- Le `Dockerfile` part de `python:3.12-slim`.
- La CI épingle `3.12`.

## Condition de sortie

Quand `torch` publiera des roues `cp314` (y compris CUDA), relever la borne à
`<3.15`, relancer la CI, et mettre cette ADR à jour plutôt que d'en écrire une
nouvelle.
